# 0.1.10 합의 계약: 모듈 실행 경계 (구현 중)

> 이 문서는 0.1.10에 넣기로 한 계약을 구현보다 먼저 적는다. 데몬·공용 SDK·모듈은 이 문서를 보고 시작한다.
> 구현한 계약은 01·02·03 문서의 제자리로 옮기고 여기에는 완료 표시와 참조만 남긴다. 이름이나 모양을 바꿔야 하면 기준 문서를 먼저 고친다.
> 근거: 모듈 구조 검토(Claude·Codex 협의, 2026-10-24, 프로젝트 스레드 "모듈 구조 설계 검토"). 사용자 의견: 모듈 작성 부담을 늘리지 않고, 규칙에 걸리면 데몬이 분명한 오류를 낸다.

## 0. 원칙

- 데몬이 규칙을 강제한다. 모듈 작성자가 규칙을 외우지 않아도 되게, 규칙에 걸린 호출은 7절의 오류 모양으로 함수 이름과 이유를 돌려준다.
- 1·2·3절은 데몬 안에서 끝난다. 모듈 작성자가 새로 하는 일은 다음뿐이다: 데이터 루트 선언(2절, 서버 폴더 밖에 데이터를 두는 모듈만), 쓰는 SDK 함수의 최소 버전 선언(4절), 사용자 값을 경로에 붙일 때 `safe_join` 쓰기(5절). HOST 파일 처리와 오류 포장은 SDK가 맡는다(6·7절).
- 신뢰 표시(`verified` 여부)와 상관없이 1·2·7절을 적용한다. 서명은 출처와 파일 불변을 뜻하고, 코드가 안전하다는 뜻이 아니다.

## 1. 플러그인 실행기 자원 상한 (합의안 A, 구현 완료)

- 기한: 격리 실행 준비(권한 부여, 서버 시작 잠금 `LaunchGate` 대기)는 기한에 넣지 않는다(0.1.9와 같다). 서버 폴더 표시 걷기가 큰 폴더에서 수십 초 걸릴 수 있어서다. 자리 기다리기·환경 준비·실행은 지금처럼 기한 안이다. 격리 실행 준비 중에도 자리는 유지한다.
- 기준 계약: [01 §7.1 실행 자원 상한](01-daemon-core.md#71-srcpluginmodrs-python-모듈익스텐션-실행기-단발-프로세스).
- 모듈 적용: [02 §2.1](02-modules.md#21-실행-방식-dsrcpluginmodrs266-463). 익스텐션·훅 적용: [03 §2.1](03-extensions.md#21-python-호출-프로토콜-plg168-332).
- `HOST:` 기반은 6절의 이관 참조를 따른다.

## 2. 모듈이 돌려준 경로의 데몬 측 경계 (합의안 B, 데몬 구현 완료)

- 실제 경로·가장 가까운 기존 조상·백업/복원·설치/마이그레이션 검사는 [01 §7.1](01-daemon-core.md#71-srcpluginmodrs-python-모듈익스텐션-실행기-단발-프로세스)에 이관했다.
- `[extensions.saba-core] data_roots`와 `user_settings`·마이그레이션 출처 규칙은 [02 §2.1](02-modules.md#21-실행-방식-dsrcpluginmodrs266-463)에 이관했다.
- 익스텐션 `i18n_dir`의 상대·실제 경로 검사는 [03](03-extensions.md)에 이관했다.
- 남은 part 3: 좀보이드 `data_home` 호환 설정·마이그레이션·첫 로드 보존. 현재 선택한 INI 폴더는 바꾸지 않는다.

## 3. 격리 없는 플랫폼의 확인되지 않은 구성요소 (합의안 C, 데몬 구현 완료)

- 플랫폼과 분리한 Python 거부 정책·지문 동의·익스텐션별 import 정책은 [02 §2.1](02-modules.md#21-실행-방식-dsrcpluginmodrs266-463)과 [03 §2.1](03-extensions.md#21-python-호출-프로토콜-plg168-332)에 이관했다.
- Rust 실행 fixture와 Linux 복사본 E2E 준비는 구성요소마다 실제 파일 지문으로 동의를 만든다. 파일 변경 뒤에는 갱신한다. 절차는 [E2E 안내](../../tests/e2e/README.md)에 있다. Windows 격리 시험은 자동 동의하지 않는다.
- 남은 part 3: 모듈·익스텐션 저장소 개발 가이드에 같은 절차를 기록한다. 게임 서버 프로세스 격리는 이번 범위가 아니다.

## 4. 공용 SDK 최소 버전 계약 (합의안 D, 검사 구현 완료·일부 이력 미확정)

- `daemon_rcon`·`i18n`의 `SINCE` 표와 `saba_audit.py` import 검사는 [02 §2.5](02-modules.md#25-공용-python-유틸-dmodules)에 이관했다. 오류는 쓴 함수·현재 선언·필요 버전을 알린다.
- `i18n.I18n`의 `0.1.1`은 공개 태그 `test23`으로 확인했다. 다른 기존 함수는 공개 origin에 대응 태그가 없어 `0.1.2`·`0.1.8` 릴리스 커밋 기준의 보수적 값을 쓴다. 최초 공개 배포 태그 기준 확정은 남아 있다.
- 남은 part 3: 모듈의 최소 코어 버전 선언과 적합성 키트의 같은 검사.

## 5. 설치·정지·경로의 의미 계약 (합의안 E)

- 첫 설치(`install_server`, 프로비저닝)에서 고른 설정을 게임 설정 파일에 쓰지 못하면 설치는 실패다: `{success:false, error_code:"settings_write_failed", message}`. 로그만 남기고 성공을 돌려주지 않는다(팰월드·좀보이드).
- 개발 가이드(`M:docs/module-development-guide.md`)와 템플릿(`M:__example`)의 `stop()`은 02 §3.4를 따른다: `managed:true`면 저장·종료 요청만 보내고 바로 돌려준다. 기다림과 강제 종료는 데몬이 한다. 요청을 보낼 길이 없으면 `graceful_stop_unavailable`이다.
- 공용 경로 도우미와 `run_lifecycle`의 경로·직렬화 오류 처리는 구현 완료다. 기준 계약은 [02 §2.5](02-modules.md#25-공용-python-유틸-dmodules)에 있다. 다음 모듈 적용과 검사는 남아 있다.
  - 모듈은 사용자 값(설정 이름, 월드 이름 등)을 경로에 붙일 때 이 도우미를 쓴다. 첫 적용: 좀보이드 `get_ini_path`의 `server_name`.
  - 모듈의 넓은 `except Exception`도 `PathOutside`는 삼키지 않고 다시 던진다(예: 좀보이드 설치 처리 `M:zomboid/lifecycle.py:1389`). 적합성 키트가 이를 검사한다.
- 적합성 키트의 정지 검사(`M:conformance/test_conformance.py:419` 부근)는 `managed:true`의 성공 기준을 "종료 요청을 받았다"로 바꾼다. 지금은 서버가 살아 있으면 성공을 거부한다.

## 6. 좁은 호스트 요청 통로 (합의안 F, 데몬·SDK 기반 구현 완료)

- 모든 실행의 `SABA_HOST_DIR`·`HOST:`·허용 작업·한계·인스턴스 문맥·자격증명 재진입은 [01 §7.1](01-daemon-core.md#71-srcpluginmodrs-python-모듈익스텐션-실행기-단발-프로세스)에 이관했다.
- `daemon_stdin_command`와 새 `daemon_rest`의 HOST/HTTP 전환은 [02 §2.5](02-modules.md#25-공용-python-유틸-dmodules)에 이관했다. 일반 토큰 경로와 `daemon_post`는 옛 모듈 호환용으로 남는다.
- 남은 part 3: 공식 모듈은 이 SDK 도우미만 사용한다. 팰월드의 `execute_rest_via_daemon`과 `PalworldRestClient` 직접 REST 경로를 도우미로 옮기며 `method`와 `path`의 endpoint 의미를 보존한다.

## 7. 모듈 호출 오류의 모양 (합의안 G, 구현 완료)

- 기준 계약과 오류 코드 표: [01 §7.1 모듈 호출 오류](01-daemon-core.md#71-srcpluginmodrs-python-모듈익스텐션-실행기-단발-프로세스).
- SDK의 `module_path_outside`·`module_bad_output`·`module_exception`: [02 §2.2](02-modules.md#22-모듈-측-디스패치-관례), [§2.5](02-modules.md#25-공용-python-유틸-dmodules).
- 익스텐션 훅: [03 §2.1](03-extensions.md#21-python-호출-프로토콜-plg168-332).
- 격리 없는 플랫폼의 거부 정책과 반환 경로 검사는 각각 3절·2절의 이관 참조를 따른다.

## 8. 이후 과제 (0.1.10 아님)

- 게임 서버 프로세스와 Linux의 OS 실행 제한, 인스턴스별 쓰기 범위.
- 순수 라이브러리(INI 파서)와 실행 제공자(SteamCMD) 분리. 실행 도구는 데몬이 중개한다.
- `SABA_TOKEN_PATH`·`daemon_post` 제거 시점.
- 측정 뒤 상주 Python 작업자 검토.
- 공통 호출 문맥을 한 곳에서 만들고, 버전 있는 입력·결과 계약으로 정리.
