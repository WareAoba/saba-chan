사용자 가이드 한국어

사바쨩 공식 사용자 가이드

여러 게임 서버를 하나의 GUI · CLI · 디스코드 봇에서 통합 관리하는 모듈형 플랫폼. 이 문서는 설치부터 REST API, 문제 해결까지 사바쨩의 모든 기능을 다룹니다.

📘 읽기 전에

이 가이드는 Windows 10/11 기준으로 작성되었습니다. 모든 경로, 명령어, 스크린샷은 기본 설치 구성을 가정합니다. 일부 Linux 경로도 함께 안내되지만, 공식 지원은 현재 Windows가 중심입니다.

1 · 소개

사바쨩(Saba-chan · サバちゃん)은 Palworld, Minecraft, Project Zomboid 등 다양한 게임 서버를 한 곳에서 관리할 수 있는 모듈형 게임 서버 관리 플랫폼입니다.

이름의 유래 — 일본어로 "서버(サーバー)"와 "고등어(鯖, さば)"의 발음이 비슷한 데서 착안한 말장난. 🐟

핵심 특징

🧩

다중 게임 지원

모듈로 무한 확장. 공식 제공 게임은 Palworld · Minecraft · Project Zomboid. 커뮤니티 매니페스트로 더 많은 게임 추가.

🔍

자동 프로세스 감지

이미 실행 중이던 게임 서버도 재시작 후 자동으로 다시 인식해 관리 대상에 포함합니다.

🖥️

이중 인터페이스

Electron GUI와 Rust TUI가 동일한 데몬을 공유합니다. 취향이나 상황에 맞게 선택 · 병용.

🛡️

크래시 저항 설계

데몬 크래시가 게임 서버에 영향을 주지 않습니다. 서버는 항상 독립 프로세스로 실행됩니다.

🔄

자동 업데이트

GitHub Releases 기반. Core · GUI · CLI · Bot · 모듈 · 익스텐션을 개별 컴포넌트로 배포 · SHA256 검증.

💬

Discord 봇 통합

디스코드 채팅에서 바로 서버 제어. 한국어 별칭, 길드별 인스턴스 필터링 지원.

☁️

클라우드 릴레이

포트 포워딩 없이 외부 네트워크에서 봇 사용 가능. 보안은 argon2id + HMAC-SHA256.

🌏

한국어 · 영어 · 일본어 · 독일어 · 스페인어 · 프랑스어 · 포르투갈어(BR) · 러시아어 · 중국어 간체/번체

2 · 시스템 요구사항

항목요구 사양
운영체제Windows 10 / 11 (공식 지원). 일부 컴포넌트는 Linux도 동작.
CPU / RAM데몬은 수십 MB 수준. 실제 리소스는 운영 중인 게임 서버에 따름.
디스크사바쨩 자체: 최소 500 MB. 게임 서버는 별도 공간 필요.
네트워크게임 서버 포트 개방 또는 클라우드 모드용 인터넷 연결.
Rust소스 빌드 시 최신 stable (인스톨러 사용 시 불필요)
Node.js18 이상 (GUI) · 20 이상 (Discord Bot). 인스톨러가 포터블로 자동 부트스트랩.
Python3.x. 모듈 lifecycle 실행 및 ffmpeg/yt-dlp 자동 설치용. 사바쨩이 격리된 venv를 구축.
✅ 포터블 원칙

인스톨러로 설치한 경우 시스템 전역에 Python/Node.js를 설치하지 않아도 됩니다. 사바쨩은 자체 python-env/ · node-env/ 디렉토리를 가지고 격리된 환경에서 동작합니다.

3 · 설치

3.1 인스톨러를 이용한 설치

사바쨩은 Tauri 2 기반 독립형 설치 프로그램(saba-chan-installer.exe)을 제공합니다.

  1. GitHub Releases에서 최신 인스톨러를 다운로드합니다.
  2. 인스톨러를 실행하고 설치 경로를 지정합니다.
  3. 인스톨러가 다음을 자동으로 수행합니다:
    • Core · GUI · CLI · Updater · Discord Bot 다운로드 및 배치
    • 포터블 Python 환경 부트스트랩 (python-env/)
    • 포터블 Node.js 런타임 부트스트랩 (필요 시 node-env/)
    • 기본 모듈(Palworld / Minecraft / Project Zomboid) 설치
    • 시작 메뉴 · 바탕화면 바로가기 생성
  4. 설치가 완료되면 바탕화면 또는 시작 메뉴에서 Saba-chan을 실행합니다.

3.2 소스에서 빌드

저장소 클론

git clone https://github.com/WareAoba/saba-chan.git
cd saba-chan

전체 빌드 (Windows PowerShell)

.\scripts\build-windows.ps1

이 스크립트는 세 개의 빌드 작업을 병렬로 실행합니다:

  1. Rust workspace — cargo build --release --workspace
    출력: saba-core.exe, saba-chan-cli.exe, saba-chan-updater.exe, saba-chan-installer.exe
  2. Electron GUI — npm run build (Vite) → npm run package (electron-builder)
    출력: Saba-chan.exe
  3. Discord Bot — npm install --omit=dev 후 디렉토리 복사

개별 빌드 / 개발 모드

# Core Daemon
cargo build --release

# GUI 개발 모드 (Vite + Electron 동시 기동)
cd saba-chan-gui
npm install
npm start

# CLI
cargo build --release -p saba-chan-cli

4 · 빠른 시작

1️⃣

사바쨩 실행

GUI(Saba-chan.exe) 또는 CLI(saba-chan-cli.exe)를 실행합니다. Core Daemon이 자동으로 시작됩니다.

2️⃣

인스턴스 생성

GUI에서 + 서버 추가 버튼, CLI에서 :instance create. 게임 선택 → 이름과 실행 파일 경로 입력.

3️⃣

서버 설정

실행 파일 경로 · 작업 디렉토리 · 포트를 설정합니다. RCON/REST 비밀번호는 자동 생성 가능.

4️⃣

서버 시작

GUI의 ▶ 버튼 또는 CLI의 ServerDetail 화면에서 서버를 시작합니다.

5️⃣

모니터링

실시간 서버 상태, 콘솔 출력, 명령어 실행. 디스코드 봇으로 원격 제어.

5.2 Core Daemon

Core Daemon(saba-core.exe)은 사바쨩의 핵심이며, 백그라운드에서 상주하며 모든 서버 관리 기능을 제공합니다.

내부 모듈역할
supervisor/프로세스 관리 (시작/정지/모니터링), 모듈 로더, 상태 머신
ipc/Axum HTTP API 서버 (기본 포트 57474) + 핸들러
instance/디렉토리 기반 인스턴스 저장소 (UUID 기반)
plugin/Python lifecycle 모듈 실행기 (stdin JSON in, stdout JSON out)
protocol/RCON (Valve Source) · REST API 클라이언트
extension/익스텐션 manifest 파싱 · Hook 디스패처
config_store/전역 설정 관리 · TOML 직렬화
validator/설정값 검증, 포트 충돌 검사
python_env/Python venv 자동 부트스트랩
node_env/Node.js 포터블 런타임 다운로더
process_monitor/외부 실행된 게임 서버 자동 감지 (2초 간격)

5.3 통신 방식

Daemon ↔ GUI / CLI

  • 프로토콜: HTTP REST API
  • 기본 주소: http://127.0.0.1:57474
  • 인증: .ipc_token 파일 기반 토큰을 X-Saba-Token 헤더로 전송
  • 401 응답 수신 시 토큰 파일을 다시 읽어 1회 재시도

Daemon ↔ 모듈 (Python)

  1. 데몬이 lifecycle.py <function_name>을 자식 프로세스로 실행
  2. config JSON을 stdin으로 전달
  3. 모듈은 결과를 stdout에 JSON으로 출력
  4. 로그는 stderr로 출력

클라이언트 Watchdog

  • GUI / CLI는 데몬에 등록(POST /api/client/register)한 후 주기적으로 하트비트를 전송합니다.
  • 모든 클라이언트가 해제된 뒤 Grace Period가 지나면 데몬은 스스로 종료됩니다.
  • 데몬이 다시 시작되면 실행 중인 게임 서버를 자동으로 재감지합니다 (STOP_COOLDOWN 동안은 억제).
상수기본값설명
DEFAULT_IPC_PORT57474기본 IPC 서버 포트
MONITOR_INTERVAL_SECS2프로세스 모니터링 주기(초)
HEARTBEAT_REAPER_INTERVAL_SECS30클라이언트 생존 확인 주기(초)
STOP_COOLDOWN_SECS30서버 정지 직후 auto-detect 억제 시간(초)

6 · GUI 사용법

사바쨩 GUI는 Electron 28 + React 18 + Vite + Zustand로 구축된 데스크톱 애플리케이션입니다.

6.1 메인 화면

GUI를 실행하면 로딩 화면이 표시되고 Core Daemon에 연결될 때까지 대기합니다. 연결 완료 후 대시보드가 표시됩니다.

등록된 서버 인스턴스는 카드 형태로 나열됩니다. 각 카드에는:

  • 서버 이름 및 게임 종류(모듈 아이콘 포함)
  • 현재 상태 (실행 중 / 정지 / 오류 · 유휴 · 외부 감지)
  • 시작(▶) / 정지(■) / 재시작 버튼
  • 익스텐션이 주입한 뱃지 (예: Docker)
  • 확장 통계 슬롯 (Docker CPU/메모리 사용량 등)

6.2 인스턴스 관리

새 인스턴스 생성

  1. 메인 화면에서 + 서버 추가 버튼 클릭
  2. 게임 선택: 설치된 모듈 목록에서 게임 선택
  3. 설정 입력: 인스턴스 이름, 서버 실행 파일 경로, 포트 등 입력
  4. 생성 완료: 메인 화면에 새 카드가 추가됨

서버 제어

  • 시작: 카드의 ▶ 버튼
  • 정지: 카드의 ■ 버튼
  • 설정: 카드 클릭 → 설정 모달 오픈
  • 삭제: 컨텍스트 메뉴(카드 우클릭)에서 삭제
  • 순서 변경: 카드 드래그 앤 드롭

설정 편집

서버 카드를 클릭하면 설정 모달이 열립니다. 각 모듈이 정의한 설정 필드가 표시되며, 타입에 따라 적절한 입력 UI가 제공됩니다.

필드 타입UI비고
text텍스트 입력placeholder / validator 지원
number숫자 입력min / max / step 지원
boolean토글 스위치SabaUI 통일 스타일
selectCustomDropdown다중 옵션 / 그룹화
password마스킹된 입력빈 값일 때 자동 생성 옵션
file파일 선택 다이얼로그Electron dialog API
folder폴더 선택 다이얼로그Electron dialog API

설정 필드는 그룹으로 분류됩니다:

  • 기본 (빈 문자열) — 일반 설정
  • saba-chan — 사바쨩 전용 설정 (포트 충돌 검사 등)
  • advanced — 고급 설정 (기본적으로 접힌 상태)

6.3 서버 콘솔

콘솔 뷰에서 서버의 실시간 stdout/stderr 출력을 확인하고, 서버에 직접 명령어를 입력할 수 있습니다.

  • ConsoleView — 메인 화면 하단 도킹 패널. 여러 서버를 탭으로 전환.
  • ConsoleWindow — 독립 팝업 창으로 분리 가능 (멀티 모니터 활용).
  • 모듈의 syntax_highlight 설정에 따라 게임별 구문 강조가 적용됩니다.
  • ANSI 이스케이프 코드 및 제어 문자는 자동으로 정리됩니다.
  • 콘솔 버퍼 크기는 전역 설정에서 변경 가능 (기본 2000줄).

6.4 설정 모달

타이틀바의 톱니바퀴 아이콘을 클릭하면 설정 모달이 열립니다.

탭설정 항목
일반언어, 자동 새로고침, 새로고침 간격
외관테마 (라이트 / 다크 / 시스템), 폰트 크기, 배경
고급IPC 포트, 콘솔 버퍼 크기, 비밀번호 자동 생성, 포트 충돌 검사
익스텐션설치된 익스텐션 관리 (활성화 / 비활성화 / 설치 / 삭제)
Discord 봇prefix, 노드 페어링, 인스턴스/멤버 권한 설정
사바 스토리지설정/인스턴스 디렉토리 열기 · 백업 · 초기화

7 · CLI 사용법

사바쨩 CLI(saba-chan-cli.exe)는 Ratatui + Crossterm 기반의 대화형 터미널 인터페이스(TUI)입니다.

7.1 TUI 화면 구성

CLI는 여러 화면(Screen) 간을 탐색하는 스택 기반 구조입니다. Esc로 뒤로 이동할 수 있습니다.

화면설명
Dashboard메인 대시보드 — 데몬/봇 상태, 서버 목록 요약
Servers인스턴스 목록 (네비게이션용)
ServerDetail인스턴스 상세 — 상태, 시작/정지/재시작/삭제

8 · 인스턴스 관리

8.1 인스턴스란?

인스턴스는 하나의 게임 서버 설정 단위입니다. 같은 게임의 서버를 여러 개 생성할 수 있으며, 각 인스턴스는 독립적인 설정과 상태를 가집니다.

인스턴스 데이터는 디렉토리 기반으로 저장됩니다:

instances/
├── order.json                  ← 인스턴스 정렬 순서
├── <uuid>/
│   ├── instance.json           ← 메타데이터 (id, name, module, ports…)
│   └── settings.json           ← 모듈별 동적 게임 설정
└── <uuid>/
    ├── instance.json
    └── settings.json

8.2 인스턴스 생성

GUI에서 생성

  1. + 서버 추가 버튼 클릭
  2. 게임 선택 (설치된 모듈 목록)
  3. 필수 설정 입력:
    • 인스턴스 이름: 구분용 이름
    • 서버 실행 파일 경로 (executable_path)
    • 작업 디렉토리 (working_dir)
  4. 선택적 설정: 포트 번호, RCON/REST 비밀번호 (자동 생성 가능), 게임별 추가 설정

CLI에서 생성

:instance create

Step 1 (게임 선택) → Step 2 (설정 입력) 위저드가 시작됩니다.

8.3 인스턴스 설정 파일 구조

  • instance.json — 인스턴스 메타데이터 (이름, 모듈, 포트, 프로토콜 정보)
  • settings.json — 모듈이 정의한 동적 게임 설정 (실행 파일 경로, 게임별 옵션 등)

설정 키는 모듈의 module.toml 파일에서 [[settings.fields]]로 정의됩니다.

8.4 서버 시작 / 정지 / 재시작

시작 흐름

  1. 인스턴스 설정 로드
  2. 모듈의 get_launch_command() 호출 → 시작 명령어 생성
  3. ManagedProcess로 서버 시작 (stdin/stdout 캡처)
  4. 프로세스 모니터링 시작 (2초 간격)
  5. 등록된 익스텐션의 server.pre_start → server.post_start Hook 디스패치

정지 흐름

  1. 모듈의 stop_server() 호출 (RCON / REST / stdin 등 프로토콜별 정지)
  2. 프로세스 종료 확인
  3. 30초간 STOP_COOLDOWN 적용 — 자동 감지 일시 억제
  4. server.post_stop Hook 디스패치

8.5 서버 프로퍼티 편집

일부 모듈은 게임 서버의 프로퍼티 파일(예: server.properties)을 직접 편집할 수 있는 기능을 제공합니다.

  • GUI: 설정 모달의 서버 프로퍼티 탭
  • CLI: ServerProperties 화면
  • API: GET /api/instance/{id}/properties, PUT /api/instance/{id}/properties

8.6 서버 명령어 실행

서버가 실행 중일 때 게임 서버에 직접 명령어를 보낼 수 있습니다:

11 · Discord 봇

사바쨩의 Discord 봇은 클라우드 릴레이 서버(saba-chan.online)에서 운영되는 공식 봇입니다. 사용자가 직접 Discord 봇 토큰을 발급하거나 봇 프로세스를 실행할 필요가 없으며, GUI에서 페어링 코드 한 번으로 연결됩니다.

11.1 봇 페어링

  1. Discord 서버에 공식 봇을 초대합니다 (GUI의 Discord 봇 → 봇 초대 버튼).
  2. GUI에서 페어링 코드 생성 버튼을 누릅니다.
  3. Discord에서 /saba-chan link code:<code> 슬래시 명령으로 코드를 입력합니다.
  4. 페어링이 완료되면 GUI에 노드 정보가 자동 등록됩니다.
💡 클라우드 릴레이 전용

로컬 봇 프로세스 모드는 v0.2 부터 폐기되었습니다. NAT 환경에서도 별도 포트 포워딩 없이 동작합니다.

11.4 별칭 시스템

명령어를 간소화하기 위한 별칭 시스템이 지원됩니다:

  • 모듈 별칭: bot-config.json의 moduleAliases + 모듈 [aliases] 섹션
  • 명령어 별칭: bot-config.json의 commandAliases + 모듈별 [aliases]

예시 (bot-config.json):

{
  "moduleAliases": {
    "팔": "palworld",
    "마크": "minecraft"
  },
  "commandAliases": {
    "켜": "start",
    "꺼": "stop"
  }
}

이렇게 설정하면:

사바쨩 팔 켜      → 사바쨩 palworld start
사바쨩 마크 꺼    → 사바쨩 minecraft stop
🔥 핫 리로드

별칭 설정 파일이 변경되면 봇 재시작 없이 즉시 반영됩니다.

길드(노드)별 인스턴스 필터링

bot-config.json의 nodeSettings에서 Discord 길드별로 명령 대상 인스턴스를 제한할 수 있습니다. 설정하지 않으면 모든 인스턴스가 대상이 됩니다.

11.5 음악 봇

YouTube 쿠키 설정 (선택)

  1. 환경 변수 YT_COOKIES_PATH의 Netscape 쿠키 파일
  2. ~/.saba-cookies/cookies.txt

14 · 릴레이 서버 (클라우드 모드)

릴레이 서버(server-chan)는 NAT 뒤에 있는 사바쨩 노드와 Discord 봇 간의 통신을 중계하는 클라우드 서비스입니다.

아키텍처

Discord 사용자
    │
    ▼
릴레이 서버 (server-chan)    ← Fastify 5 + PostgreSQL 17
    │
    ▼ (Long Poll)
로컬 사바쨩 노드              ← 봇 (릴레이 에이전트 모드)
    │
    ▼ (IPC)
로컬 Core Daemon
    │
    ▼
결과 → 릴레이 서버 → Discord 응답

주요 원칙

  • 중앙 서버는 payload를 해석하지 않음 (택배 기사 역할만 수행)
  • Pull 모델: 노드가 릴레이 서버로 접속하므로 포트 포워딩이 필요 없음
  • IP 정보 미저장: 프라이버시 보호
  • 보안: argon2id 토큰 해싱 + 요청별 HMAC-SHA256 서명

인증 프로토콜

각 요청은 다음 헤더를 포함해야 합니다:

Authorization: Bearer <sbn_TOKEN>
x-request-timestamp: <unix seconds>
x-request-nonce: <unique request id>
x-request-signature: HMAC-SHA256(method\nurl\nts\nnonce\nbody, secret)

토큰 형식: sbn_<nodeId>.<secret>. 사바쨩 GUI의 "페어링" 플로우에서 발급받습니다.

복구 불가 인증 오류

다음 에러를 수신하면 봇이 로컬 토큰을 삭제하고 재페어링을 유도합니다:

  • NODE_NOT_FOUND — 서버에 호스트 없음
  • INVALID_TOKEN — 토큰 해시 불일치
  • INVALID_TOKEN_FORMAT — sbn_ 형식 아님
  • MISSING_TOKEN — Bearer 헤더 누락
  • INVALID_SIGNATURE — HMAC 불일치

클라우드 모드 설정

  1. GUI의 Discord 봇 모달에서 클라우드 모드로 전환하고 페어링을 진행 → 릴레이가 노드 토큰을 발급
  2. 또는 CLI에서 수동 설정: 
    :bot mode cloud
:bot relay https://saba-chan.online
:bot node-token sbn_<id>.<secret>
  3. 봇을 시작하면 릴레이 에이전트 모드로 동작합니다.

18 · 문제 해결

데몬에 연결할 수 없음

증상: GUI 로딩 화면에서 멈추거나, CLI에서 연결 오류 표시.

해결 방법:

  1. saba-core.exe가 실행 중인지 작업 관리자에서 확인합니다.
  2. IPC 포트(기본 57474)가 다른 프로그램에 의해 사용 중인지 확인 (netstat -ano | findstr 57474).
  3. 방화벽이 로컬 연결을 차단하고 있지 않은지 확인.
  4. .ipc_token 파일이 존재하는지 확인.
  5. 필요 시 CLI에서 :daemon restart.

서버가 시작되지 않음

증상: 시작 버튼을 눌러도 서버가 실행되지 않음.

해결 방법:

  1. executable_path가 올바른 실행 파일을 가리키는지 확인.
  2. working_dir이 유효한 디렉토리인지 확인.
  3. 서버 콘솔에서 에러 메시지 확인.
  4. 포트 충돌 여부 확인 (:instance validate <id> 또는 GUI 진단 버튼).
  5. Windows Defender / SmartScreen이 실행 파일을 차단하지 않는지 확인.

모듈이 로드되지 않음

증상: 모듈 목록에 게임이 표시되지 않음.

해결 방법:

  1. 모듈 디렉토리 경로 확인 (SABA_MODULES_PATH 환경변수 또는 %APPDATA%\saba-chan\modules).
  2. module.toml과 lifecycle.py가 모듈 디렉토리에 있는지 확인.
  3. :module refresh 실행.
  4. Python 격리 환경(python-env/)이 생성되어 있는지 확인.

Discord 봇이 응답하지 않음

  1. 봇 토큰이 올바르게 설정되어 있는지 확인 (:bot status).
  2. 봇이 실행 중인지 확인.
  3. Discord 개발자 포털에서 MESSAGE CONTENT INTENT를 활성화했는지 확인.
  4. 봇이 해당 Discord 서버에 초대되어 있고 메시지 읽기/쓰기 권한이 있는지 확인.
  5. prefix가 올바른지 확인 (기본 사바쨩).
  6. 로컬 모드에서 봇이 2개 이상의 길드에 있다면 단일 길드로 줄이거나 클라우드 모드로 전환.

음악 봇이 "재생 실패"를 반환함

  1. 로컬 모드: ffmpeg · yt-dlp가 부트스트랩되었는지 확인 — 익스텐션 디렉토리의 .deps-resolved.json 참조.
  2. 원격 모드: YouTube 봇 챌린지일 가능성 — ~/.saba-cookies/cookies.txt에 브라우저 로그인 쿠키를 배치하거나 YT_COOKIES_BROWSER 환경변수를 설정.
  3. 볼륨이 너무 낮거나 높아 음성 채널에서 들리지 않는지 확인 (사바쨩 music volume 80).

업데이트 실패

  1. 인터넷 연결 확인.
  2. GitHub API 접근 가능 여부 확인.
  3. :update status로 현재 상태 확인.
  4. 수동으로 다시 시도: :update check → :update download → :update apply.
  5. 실패가 반복되면 Releases 페이지에서 최신 인스톨러로 재설치.

19 · FAQ

Q. 사바쨩이 크래시하면 게임 서버도 꺼지나요?

A. 아닙니다. 사바쨩은 게임 서버를 독립 프로세스로 관리하므로, 사바쨩(Core Daemon)이 크래시하더라도 게임 서버는 계속 실행됩니다. 사바쨩을 다시 시작하면 실행 중인 서버를 자동으로 재감지합니다.

Q. 같은 게임의 서버를 여러 개 운영할 수 있나요?

A. 네. 같은 모듈로 여러 인스턴스를 생성할 수 있습니다. 각 인스턴스는 독립적인 설정(포트, 디렉토리 등)을 가집니다.

Q. 새로운 게임을 추가하려면 어떻게 하나요?

A. 모듈을 개발하거나 원격 매니페스트에서 커뮤니티 모듈을 설치하면 됩니다. Core를 재컴파일할 필요가 없습니다. 개발 가이드는 saba-chan-modules 리포지토리를 참조하세요.

Q. GUI와 CLI를 동시에 사용할 수 있나요?

A. 네. 둘 다 같은 Core Daemon에 연결되므로 동시 사용이 가능합니다. 각 클라이언트는 독립적으로 데몬에 등록되고 동기화됩니다.

Q. 원격에서 서버를 관리할 수 있나요?

A. Discord 봇을 통해 원격 제어가 가능합니다. NAT 뒤에 있어 포트 포워딩이 불가능한 경우 클라우드 모드(릴레이 서버)를 사용하세요.

Q. Docker로 게임 서버를 격리할 수 있나요?

A. 네. docker 익스텐션을 활성화하면 게임 서버를 Docker 컨테이너에서 격리 실행할 수 있습니다. 인스턴스 설정에서 docker_enabled를 켜고 CPU/메모리 제한을 설정합니다.

Q. 지원하는 언어를 변경하려면?

A. GUI 설정 → 일반 → 언어에서 변경하거나, CLI에서 :config set language <lang_code>를 실행합니다. 지원 코드: en, ko, ja, de, es, fr, pt-BR, ru, zh-CN, zh-TW.

Q. 데몬 로그는 어디서 확인하나요?

A. %APPDATA%\saba-chan\daemon.log에 기록됩니다. GUI/CLI 콘솔에도 주요 이벤트가 실시간으로 표시됩니다.
